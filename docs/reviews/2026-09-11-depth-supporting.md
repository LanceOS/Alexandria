# Supporting curriculum: tutorial depth expansion

Authored and checked on **2026-09-11**. This record covers **22 modules in 11 supporting subjects**, retaining their existing three-part layout and prior accuracy corrections. Each module now develops its model and vocabulary, explains the original trace, works through a contrasting scenario, and provides **three explained reflections, one in each part**. The first checkpoint follows the conceptual teaching, the second follows the worked scenarios, and the original checkpoint remains in the final practice part. Five moved prompts explicitly restate their model or assumptions so they do not depend on material introduced later. The additional teaching is distributed through the original parts rather than placed in an appendix.

The modules contain **24,426 explanatory words**, excluding code, citations, titles, and objectives; individual counts range from **1,062 to 1,144**. Counts describe scope, not evidence of educational effectiveness. The intended improvement is the reasoning between definitions, operations, results, and practice—not length by itself. Existing module discovery metadata, release IDs/numbers, and all **66 stable part IDs** were preserved during this authoring step. The parent task manages release assignment and publication separately.

## Evidence inspected for this expansion

Primary references were opened and relevant passages read during authoring; a search-result title was not treated as verification. Original hypothetical arithmetic and design reasoning are distinguished from claims made by those sources. Existing references and historical research qualifications remain in each module.

- [Hoare][hoare]: notation connecting preconditions and completion results, composition, and iteration (§§3.1–3.4). Used for the reasoning pattern, not as a claim that these new exercises were published in the paper. The prior audit's limits on historical review-policy verification remain.
- [Parnas][parnas]: the original journal scan's “The Criteria” section and adjacent boundary example. It supports decision/knowledge hiding; the new reading-log scenarios are original analysis. This inspection used the actual scan, not the previously misidentified overview or blocked DOI page. No fresh claim about publisher review-policy access is made.
- [Goldberg][goldberg]: the authorized edited reprint's introduction, Rounding Error, Floating-point Formats, and Relative Error and Ulps. New decimal examples were calculated independently. This is historical published research exposition, not the current IEEE 754 normative text or a measurement of `double` on every implementation.
- [Kalibera and Jones][kalibera]: accepted-manuscript abstract on uncertainty and choosing repetition levels. The previous audit's broader inspection and ISMM provenance remain in the existing reference; this expansion does not claim to have rerun experiments or freshly re-read every statistical derivation.
- [NIST queue][queue], [binary search][binary], and [big-O][big-o]: FIFO operations, sorted interval halving, finite-index midpoint reasoning, comparison versus traversal costs, and formal asymptotic upper bounds. The ring implementation and query break-even figures are original models.
- [Cachegrind][cachegrind]: overview, simulation limitations and Accuracy. This supports separating a simplified cache count from processor timing. The two-line LRU machine is explicitly invented; it is not presented as the current hardware cache or a complete Cachegrind model.
- [Linux memory concepts][linux-memory]: Virtual Memory Primer and Anonymous Memory. [N4861 basic.life][lifetime]: lifetime start/end requirements; [glibc free][glibc-free]: documented allocator release behavior. These are separate layers and implementation scopes.
- [LLNL][llnl]: Amdahl's fixed-workload formulas and strong/weak scaling distinction. [OpenMP 5.2 memory model][openmp]: shared/private storage, unordered accesses and lifetime concerns. The lesson schedules use stronger expressly stated abstract assumptions; they are not executions of racy C++.
- [Core Guidelines][guidelines]: explicit-interface rationale and CP.21/CP.22 discussion of multiple locks and callbacks. These are expert recommendations, not normative language rules or empirical performance findings.
- [CMake 3.31 buildsystem][cmake]: target usage requirements and consumer propagation. [add_custom_command][cmake-custom]: generation signature, outputs, dependencies and byproducts. No complete CMake project was executed for the hypothetical scheduling calculation.
- [Reproducible Builds definition][repro] and [build-path guidance][build-path]: declared inputs/artifacts, byte comparison, and paths in output. The package-date case declares its own invented packaging behavior; it is not an untested assertion about a particular archive tool.
- [Google Benchmark][benchmark]: optimization-control limits, statistics/reporting context and interleaving. [GoogleTest][gtest]: independent/repeatable tests and observable assertions. No benchmark was run and no claimed speed improvement comes from the invented numbers.
- [libFuzzer 18.1.8][fuzzer]: repeated target invocation, arbitrary input tolerance, deterministic/fast target guidance and corpus use. [QuickCheck 2.16.0.0 API][quickcheck]: generator quality and shrinking. No fuzzing campaign or property-testing implementation was executed for these conceptual lessons.

[Authorization][authorization]: deny-by-default and permission validation on every request. [CWE-400][cwe400]: limited-resource control, throttling, scale limits and safe failure. The `.txt` route supplies the inspected full-text passages; the shorter URL redirected to the RFC information page. The module's locator identifies the inspected route.

Checkpoint placement was reviewed against preceding teaching; five moved prompts were clarified to state their assumptions. The original reflection remains in the final practice part. Each part contains expanded topic-specific teaching. Module/release identities and discovery metadata were compared with `HEAD` and unchanged during this subtask.
- No full application test suite, production build, live database operation, commit, timing experiment, real hardware cache experiment, fuzz campaign, or external educational study was performed by this authoring subtask. Publication and whole-catalog integration are handled by the parent task.
- These modules teach their defined objectives in depth; two modules do not exhaust an entire discipline. The original lessons have not undergone independent academic peer review. Published-paper provenance and access limits from the earlier audit were preserved rather than upgraded merely because the content grew.

## Independent review closure

A separate internal reviewer read all 22 expanded modules, including calculations, cases, practice placement and source locators. One inconsistency in a newly added test-design trace was corrected: rejection is specified for the concrete above-range digit sequence 999999999999999999999999, while many leading zeros followed by 1 are explicitly accepted under the stated contract. The reviewer verified that both outcomes follow from the digit-only grammar, permitted leading zeros and final value range 1..120. No new input-length restriction was invented. All original code/trace blocks remain unchanged; this correction affects a new contrasting case. No further actionable findings remained.
