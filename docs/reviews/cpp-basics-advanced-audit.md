# C++ Basics and advanced lesson audit

Baseline: `99a387f`. Reviewed 2026-09-11. Scope: all 19 modules in Basics, Advanced Templates, Compile-time Programming, Object Model and Memory, C++ Concurrency, Coroutines and Async, and Library Engineering; 77 citation records referring to 63 distinct URLs. The remaining 22 C++ modules are covered by the separate core audit.

**Outcome:** no factual correction or unsafe runnable example identified in these 19 modules under their stated assumptions. Two evidence qualifications remain: the 27 Basics draft citations use a changing draft, and the seven book citations could only be checked for metadata and section identity in this audit. Those qualifications prevent an unconditional claim that every cited passage was independently verified. No lesson or published database content was changed.

## Method

Read every objective, paragraph, code block, worked output, practice prompt, reflection explanation and reference in the scope. Freshly opened all cited documentation locations and compared relevant passages. For long specification sections, inspected the paragraphs governing the taught behavior, not every unrelated rule. Checked the historical concurrency paper's abstract and introduction, publication identity and institutional peer-review classification. The DOI endpoint was unavailable, so the paper was inspected through accessible university copies.

The catalog's example checker independently compiled and executed all 46 runnable C++ examples, including this scope, with GCC 16.2.1 and `-std=c++20 -Wall -Wextra -Werror -pedantic-errors -pthread`; all expected outputs matched. Execution supplements the language-level reasoning below; it does not prove portability across every implementation, arbitrary-input safety or correctness under every thread schedule.

## Source identity and evidence limits

### BAS-R01 — Preserve the Basics reference edition

The seven Basics lessons contain **27 citation instances to 25 distinct `eel.is/c++draft` URLs**. These links identify the current draft, not a frozen C++20 edition. The reviewed elementary claims remain correct, and the records already state an access date, so this is a reproducibility improvement rather than a demonstrated false lesson. In a future content release, pin the supporting paragraphs to N4861 or a recorded draft revision and include the draft identifier in the title/locator, following the advanced units' existing pattern. Check paragraph relocation individually rather than replacing URL prefixes blindly. [Current draft](https://eel.is/c++draft/), [N4861](https://timsong-cpp.github.io/cppwp/n4861/).

As spot checks across the edition boundary, the hosted-main return rule, `endl` effects and input-sentry tie behavior were also compared with the frozen C++20 text. No conflict was found for the lesson claims. [N4861 main](https://timsong-cpp.github.io/cppwp/n4861/basic.start.main), [output manipulators](https://timsong-cpp.github.io/cppwp/n4861/ostream.manip), [input sentry](https://timsong-cpp.github.io/cppwp/n4861/istream.sentry).

### BAS-L01 — Book passages were not freshly verified

All seven book records correctly identify Bjarne Stroustrup, *The C++ Programming Language*, fourth edition, Addison-Wesley, 2013, ISBN 9780321563842. The author's official page confirms this metadata. Its extended contents confirms the cited section identities for the introductory basics, `if`, `for`, `while`, functions, manipulators and buffering. [Author's book page](https://www.stroustrup.com/4th.html), [extended contents](https://www.stroustrup.com/4thContents.html).

The local book mount was unavailable during this audit, and the author's linked chapter sample returned HTTP 403. Accordingly, the printed page numbers and passages in Basics 1–6 were **not independently rechecked** here. A contents page establishes section identity, not the contents or page numbers of that section. Basics 7 already limits its book reference to further reading and section-title verification; that label is accurate. The independently inspected standard passages support the taught language rules, but do not substitute for verifying a claim that a particular book page says something.

### Historical concurrency paper

Boehm and Adve, “Foundations of the C++ Concurrency Memory Model,” PLDI 2008, pp. 68–78, DOI 10.1145/1375581.1375591, is correctly identified. The abstract and introduction in both the author-group and SFU copies support the lesson's limited historical rationale for language-level concurrency semantics. They do not specify C++20 `jthread`, atomic waiting or the final modern memory model. Those rules are independently cited to N4861. [Author-group copy](https://rsim.cs.illinois.edu/Pubs/08PLDI.pdf), [SFU copy](https://www.cs.sfu.ca/~ashriram/Courses/CS7ARCH/papers/boehm-pldi-2008.pdf).

The institutional proceedings record confirms title, authors, publication year, page range and conference DOI. A separate institutional record for the same paper's SIGPLAN Notices publication explicitly classifies it as peer-reviewed; it carries the journal DOI 10.1145/1379022.1375591. The proceedings record's event-date field incorrectly says 2007; the paper's own imprint says June 7–13, 2008, so that erroneous event field was not used. The citation in the lesson remains correct. [Proceedings metadata](https://experts.illinois.edu/en/publications/foundations-of-the-c-concurrency-memory-model-2/), [institutional peer-review classification](https://experts.illinois.edu/en/publications/foundations-of-the-c-concurrency-memory-model/).

### Documentation and guidance

All cited N4861/N4950 locations were reachable, and the reviewed clauses agree with their stated uses. They are public committee drafts reproduced in an HTML mirror, not the purchased ISO publication. N4950 references are correctly limited to later features: `if consteval`, `std::generator` and `std::expected`.

The Core Guidelines recommendations are expert guidance, not empirical research or mandatory language rules. SL.io.50 supports avoiding unnecessary explicit flushes; I.27 supports Pimpl as an implementation-boundary technique with tradeoffs. The lesson's GNU ABI claims agree with that toolchain's API/ABI definition and compatibility constraints, without promising cross-toolchain compatibility. [SL.io.50](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Rio-endl), [I.27](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Ri-pimpl), [GNU ABI policy](https://gcc.gnu.org/onlinedocs/libstdc++/manual/abi.html).

## Release and coverage limits

These are bounded introductory lessons, not complete treatments of their disciplines. No independent paper replication, ABI compatibility experiment, production coroutine runtime review, model checking or multi-compiler conformance campaign was performed. The review did not treat a successful compile as evidence that every explanatory statement or bibliographic locator is correct.

No language-rule correction is proposed for these 19 modules. For a future release, resolve BAS-R01 and obtain the licensed book again to close BAS-L01. Published lesson versions and their source associations are immutable in Alexandria; any later changes must use an appropriate content-version workflow rather than rewriting previously published records.
