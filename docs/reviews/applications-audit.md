## Detailed findings

### APP-001 — Qualify what survives a scene-child rename

In `game-development/scene-composition/01-instance-state.json`, the worked trace renames `HealthLabel` and then attributes the successful second call entirely to the root-level interface. Encapsulation keeps external callers independent of child paths, but an internal lookup can still break. The Godot documentation explicitly ties lookup paths to node names. Add an internal path-update step and explain that external callers remain unchanged while the scene implementation maintains its bindings. A retained valid reference is another possible implementation. This is a missing assumption in the teaching claim; the health arithmetic is correct. [Godot node paths](https://docs.godotengine.org/en/stable/tutorials/scripting/nodes_and_scene_instances.html).

### APP-002 — Distinguish a missing direct edge from independence

In `machine-learning-infrastructure/tensor-execution/01-graph-and-data.json`, the reflection assumes independence from the absence of a dependency edge. The lesson itself supplies a counterexample: `MatVec` and `ReLU` are connected through `Add`. Rewrite the question to assume no direct or indirect dependencies and no conflicting shared state, and preserve the valid explanation that permitted parallelism need not improve speed. The dependency counterexample is an independent logical deduction from the authored graph; the cited paper supports the graph-input execution model. [TensorFlow paper, sections 3 and 3.1](https://www.usenix.org/system/files/conference/osdi16/osdi16-abadi.pdf).

## Limits

The review verifies the stated finite models and selected cited contracts. It does not certify complete application courses, production implementations, real-time bounds, actual device scheduling, filesystem durability under faults, deterministic replay, or measured performance. Source inspection is not experimental reproduction. Full papers were accessed for relevant passages and metadata, not independently replicated or exhaustively reviewed with all their bibliographies.

The FFTW equation images were not extracted. Its adjacent text states the sign, output order and normalization convention; the lesson explicitly gives its own complete DFT formula, which was checked independently. ROS sources were reviewed as official Jazzy repository text. Current framework/library versions observed in web documentation are not assertions about installed local runtimes.

Corrections are proposed for review in the companion JSON. Applying them should be followed by the repository content checks and any required published-content version/import workflow; this audit itself makes no such mutation.
